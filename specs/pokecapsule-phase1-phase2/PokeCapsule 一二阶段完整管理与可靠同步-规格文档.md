# 项目规格：PokeCapsule 一二阶段完整管理与可靠同步

**版本：** 1.0
**日期：** 2026-07-28
**状态：** 可以开始实现
**系统类型：** 本地优先语音胶囊管理

## 1. 目标

### 问题陈述

现有系统只能在线操作，删除后没有可见恢复入口，Mac 离线修改无法回写，文本缺少用户最终编辑层，也缺少搜索、智能筛选、批量复制和自动备份。

### 成功标准

- [ ] Poke3 和 Mac 都能查看回收站、恢复胶囊和确认后永久删除
- [ ] Mac 离线执行移动、标签、收藏、编辑和删除后会形成持久队列，重连后安全同步
- [ ] 设备端数据版本与离线操作预期版本不一致时，冲突项暂停并显示原因
- [ ] 每次成功同步后 Mac 自动创建有保留策略的本地备份
- [ ] Poke3 和 Mac 都能按转写文字、最终文字、标签和目录搜索
- [ ] 用户可以编辑 final.md，原始转写与校对文本保持不变
- [ ] Poke3 和 Mac 都能查看待转写、失败、最近删除等智能视图
- [ ] Mac 可以批量复制纯文本或 Markdown，Poke3 可以批量复制可导出的胶囊内容

### 交付等级与真实性证据

**目标等级：** `real_smoke`

| 能力 | 需要的真实证据 | 允许的模拟 | 缺证据时声明上限 |
| --- | --- | --- | --- |
| 回收站与恢复 | 真实 Poke3 上删除一条胶囊、双端看到回收站、恢复后回到原目录；原目录缺失时进入 Inbox | 单元测试可以使用临时文件树 | unverified |
| Mac 离线队列 | 断开 ADB 后在 Mac 执行至少两项操作，重连后真实 Poke3 数据按顺序更新且队列清空 | 单元测试可以使用假传输层 | unverified |
| 版本冲突保护 | 离线期间修改设备端同一胶囊，重连后队列停止该项并显示冲突，设备内容未被覆盖 | 文件级集成测试可构造不同 revision | unverified |
| 全文搜索与最终文字编辑 | 在两端搜索同一关键词命中胶囊，编辑 final.md 后两端显示最终文字，同时 raw.txt 与 polished.md 校验未变 | UI 预览可使用示例数据 | unverified |
| 自动备份与恢复材料 | 完成真实同步后生成带清单的时间戳备份，备份含音频、元数据与文本层 | 临时目录测试可以验证保留策略 | unverified |

**允许后置的真实验证：**

- 无线同步、云同步和多设备合并不在本轮验证范围
- Poke3 本地大模型转写不在本轮实现范围
- 跨用户权限和加密数据库不在本轮实现范围

**需要更新规格的触发条件：**

- 需要同时连接第二台 Poke3
- 需要在局域网或互联网同步
- 需要多用户账户或共享胶囊
- 胶囊数量超过一万且搜索性能不足
- 需要从备份一键整库恢复

### 范围之外

- 刷写 Poke3 系统或替换文石底层
- 云账号、多用户权限和团队协作
- 无线同步和公网服务

- SQLite 数据迁移
- 自动永久清空回收站

## 2. 系统定位

### 主要目的

让使用者在 Poke3 上低功耗录音，在 Poke3 与 Mac 上安全整理、检索、编辑、恢复和复制胶囊。

### 主要关系

Poke3 保存胶囊事实数据，Mac 保存镜像、离线操作队列和备份，并在重新连接后按版本安全回写。

### 系统方向

录音事实保全为主，双端整理和检索为辅。

### 核心流程

- 在 Poke3 上录音并生成 Inbox 胶囊
- 插电且连接 Wi-Fi 时按配置异步转写
- 在 Poke3 或 Mac 上搜索、查看、编辑最终文字、移动、加标签和收藏
- Mac 未连接设备时记录操作，重新连接后自动校验版本并同步
- 删除进入回收站，支持恢复或明确永久删除
- 同步成功后在 Mac 留存可恢复备份

### 第一版边界

本轮实现单用户、单台 Poke3、ADB 有线连接、本地文件协议、30 天回收站、离线队列、冲突提示、自动备份、全文搜索、最终文字编辑、批量复制和智能视图。

### 保护重点

- audio.m4a 原始录音不可被编辑操作覆盖
- raw.txt 和 polished.md 保持来源分层，用户编辑只写 final.md
- 离线队列遇到版本变化时暂停冲突项，不能静默覆盖
- 删除可恢复，永久删除必须再次确认
- 同步失败时保留旧镜像、待处理队列和最近备份

**规则：** 后续对象、状态、模块、测试和工作包都要服务这一定位。新增会改变主要目的、主要关系或核心流程的需求前，必须先更新规格。

## 3. 领域模型

| 对象 | 说明 | 关键字段 |
| --- | --- | --- |
| 胶囊 | 一段原始录音及其元数据和多层文字 | id, revision, createdAt, durationSeconds, folder, tags, favorite, processingStatus, audio.m4a, raw.txt, polished.md, final.md |
| 回收站记录 | 删除胶囊的可恢复元数据 | capsuleId, trashedAt, originalFolder, trashDirectory, revision |
| 待同步操作 | Mac 离线期间记录的可重放命令 | commandId, operation, capsuleIds, payload, expectedRevisions, createdAt, state, error |
| 同步冲突 | 待同步操作预期版本与设备现状不一致的可处理记录 | commandId, capsuleId, expectedRevision, actualRevision, reason |
| 备份快照 | Mac 在成功同步后保存的可核验文件快照 | createdAt, deviceSerial, manifest, capsuleCount, sourceRevisionDigest |

**规则：** 这些是系统骨架。其他数据要么是这些对象的属性，要么是它们之间的关系。新增顶层对象前，必须先更新规格。

### 对象关系

| 关系 | 类型 | 说明 |
| --- | --- | --- |
| 胶囊 -> 回收站记录 | 零或一 | 胶囊被软删除后对应一条回收站记录 |
| 待同步操作 -> 胶囊 | 多对多 | 一个批量操作可以影响多条胶囊，同一胶囊也可以按顺序累计多个离线操作 |
| 待同步操作 -> 同步冲突 | 一对多 | 一个批量离线操作可能因多条胶囊版本变化产生冲突 |
| 备份快照 -> 胶囊 | 一对多 | 每个备份快照保存一次同步后可见的全部胶囊文件 |

### 状态与动作

| 对象 | 状态 | 允许动作 | 禁止跳转或限制 |
| --- | --- | --- | --- |
| 胶囊 | raw_ready, transcribing, ready, failed, trashed | 录音, 转写, 编辑最终文字, 移动, 加标签, 收藏, 删除, 恢复, 永久删除 | 原始录音不可覆盖；编辑最终文字增加 revision；删除写 trash.json；恢复优先原目录，原目录不存在时进入 Inbox。 |
| 待同步操作 | queued, applying, conflict, failed, completed | 入队, 版本校验, 应用, 重试, 丢弃冲突项 | 队列持久化并按创建顺序执行；任一胶囊 revision 不符时该命令进入 conflict，不覆盖设备。 |

### 时间、操作记录和派生数据

| 类型 | 名称 | 来源或触发 | 处理要求 |
| --- | --- | --- | --- |
| 操作记录 | 离线操作入队 | Mac 使用者 / 设备未连接且执行可离线操作时 | 记录命令、目标胶囊、预期 revision、时间和 payload |
| 操作记录 | 同步冲突 | 同步协调器 / 设备 revision 与预期不一致时 | 记录命令、胶囊、预期与实际 revision 和原因 |
| 操作记录 | 删除与恢复 | 设备使用者 / 胶囊进入或离开回收站时 | 记录原目录、删除时间、恢复目录和 revision |
| 操作记录 | 创建备份 | Mac 同步协调器 / 一次设备同步完整成功后 | 记录设备序列号、时间、胶囊数和清单摘要 |
| 派生数据 | 展示文字 | 按 final.md、polished.md、raw.txt、录音标题的优先级选择 | 实时计算，不单独保存 |
| 派生数据 | 全文搜索结果 | 最终文字、校对文字、原始转写、标签、目录和时间 | 内存索引，启动或同步后重建 |
| 派生数据 | 智能视图 | processingStatus、trashedAt、favorite、createdAt | 实时筛选，不单独保存 |
| 派生数据 | 同步摘要 | 待同步操作、冲突和最近同步时间 | Mac 本地状态持久化 |

## 7. 数据流

```text
Poke3 录音与文件树 -> Android 存储与命令处理 -> Mac 镜像与扫描器 -> Mac 离线队列与同步协调器 -> Poke3 与 Mac 管理界面 -> Mac 备份快照
```

| 节点 | 作用 | 说明 |
| --- | --- | --- |
| Poke3 录音与文件树 | producer | 产生 audio.m4a、capsule.json、processing.json 和各层文字 |
| Android 存储与命令处理 | process | 校验 revision 后执行编辑、移动、标签、收藏、删除、恢复和永久删除 |
| Mac 镜像与扫描器 | process | 拉取设备文件树并生成双端管理模型 |
| Mac 离线队列与同步协调器 | process | 记录离线操作，重连后校验并按序回放，产出冲突和同步状态 |
| Poke3 与 Mac 管理界面 | consumer | 展示搜索、智能视图、回收站、详情、批量操作和同步反馈 |
| Mac 备份快照 | consumer | 保存每次成功同步后的完整恢复材料和清单 |

图例：Producer = 数据起点，Process = 处理，Consumer = 最终使用者或结果。

## 8. 决策记录

### [ARCHITECTURE] 决策：继续使用本地文件事实源
- 选择：Poke3 文件树继续作为事实源，Mac 保持镜像、队列和备份
- 备选方案：迁移到 SQLite 或让 Mac 成为主库
- 理由：现有录音与转写流程已经围绕文件工作，文件可直接备份、播放和恢复，当前规模无需数据库迁移成本
- 带来的约束：写操作必须通过 revision 检查，Mac 镜像不能直接宣称为设备事实
- 以后改动代价：MEDIUM（中）
### [DATA] 决策：增加 final.md 作为用户最终文字
- 选择：展示优先级为 final.md、polished.md、raw.txt、默认标题
- 备选方案：直接覆盖 polished.md
- 理由：用户编辑和模型校对来源不同，分层后可以追溯并防止误覆盖
- 带来的约束：编辑 final.md 不得修改 raw.txt 和 polished.md
- 以后改动代价：HIGH（高）
### [SYNC] 决策：离线操作以命令队列回放
- 选择：Mac 持久化命令和 expectedRevisions，重连后按序应用
- 备选方案：直接比较并覆盖整份镜像
- 理由：命令粒度更容易审计和发现冲突，也能沿用现有设备命令入口
- 带来的约束：冲突项暂停，后续依赖同一胶囊的命令不能越过执行
- 以后改动代价：MEDIUM（中）
### [RETENTION] 决策：回收站默认保留 30 天且不自动永久删除
- 选择：显示 30 天保留提示，永久删除必须由用户确认
- 备选方案：删除即永久删除或后台自动清空
- 理由：语音胶囊难以重建，设备容量压力目前低于误删风险
- 带来的约束：回收站内容仍计入设备空间，界面要显示数量和空间提示
- 以后改动代价：HIGH（高）
### [SEARCH] 决策：首版采用内存全文索引
- 选择：启动和同步后从文件扫描结果重建小型索引
- 备选方案：SQLite FTS 或嵌入式搜索引擎
- 理由：当前数据量小，减少常驻写入、迁移和 Poke3 耗电
- 带来的约束：数量超过一万或搜索明显变慢时重新评估
- 以后改动代价：HIGH（高）
### [BACKUP] 决策：同步成功后自动创建 Mac 备份
- 选择：备份真实镜像并生成 manifest，默认保留最近 10 份和 30 天内快照
- 备选方案：只保留最新镜像
- 理由：镜像会随同步覆盖，独立快照才能应对延迟发现的误删和协议错误
- 带来的约束：备份失败要提示，但不能破坏当前镜像和设备数据
- 以后改动代价：HIGH（高）

## 10. 规格更新触发条件

实现过程中遇到以下情况，AI IDE 必须停下来，回到规格作者确认：

1. 需要支持第二台设备
2. 需要无线或云同步
3. 需要多人访问或权限隔离
4. 胶囊数据量超过一万
5. 需要全库一键恢复
6. 转写服务的数据格式发生不兼容变化
7. 需要对原始音频做编辑或降噪

---

## 11. 反模式

- Mac 断连时直接修改镜像并假设它会自动成为设备事实
- 用更新时间覆盖 revision 冲突判断
- 用户编辑时覆盖 raw.txt 或 polished.md
- 删除时只移动目录却不记录原目录和删除时间
- 把 ADB、文件操作和冲突判断写进 SwiftUI 视图
- 把回收站、搜索和命令处理继续塞进单个巨大类
- 为了未来规模提前引入数据库、服务端和账号系统
- 用模拟测试代替真实 Poke3 联调结论

## 12. 给 AI 实施者的说明

文档里的决策记录是约束。遇到规格没有覆盖的情况，不要自行推断解决方案，先标成待确认问题并停止。
